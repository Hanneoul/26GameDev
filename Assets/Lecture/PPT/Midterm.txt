[유니티 2D 기초 실기 평가 시험지]

공통 시험 환경 세팅
프로젝트 템플릿: Unity 2D URP (Universal Render Pipeline)
Game 뷰 해상도: 1920x1080 (16:9 Full HD) 고정
Main Camera: Projection을 Orthographic으로 설정하고 Size를 5.0으로 맞출 것.

문제 1: 카메라 뷰포트 정렬 및 스프라이트 크기·위치 배치

[문제 설명]
화면 중앙에 기준이 되는 2D 스프라이트를 띄우고, 카메라가 이를 정확한 비율과 위치로 비추고 있는지 확인한다.

[세부 요구사항]
- Main Camera의 Background 색상을 진한 회색(#222222)으로 변경함.
- Camera 컴포넌트의 Size가 정확히 5.0으로 설정되어 있는지 확인함.
- Hierarchy 창에서 2D Object -> Sprites -> Square를 생성하고 이름을 'Target_Square'로 변경함.
- Transform Position을 (X: 0, Y: 0, Z: 0)으로 설정함.
- Scale을 (X: 2, Y: 2, Z: 1)로 설정하여 화면 중앙에 배치함.

[채점 기준]
Game 뷰에서는 회색 배경 위에 하얀색 사각형이 정중앙에 떠 있어야 함.
Scene 뷰에서는 카메라의 직교 투영 가이드 라인(Camera Frustum) 내부에 사각형이 완전히 포함되어 있어야 함.



문제 2: 스프라이트 레이어(Sorting Layer) 및 렌더링 순서 설정

[문제 설명]
두 개의 스프라이트를 동일한 좌표에 겹쳐서 배치하고, 렌더링 우선순위를 올바르게 설정하는지 확인한다.

[세부 요구사항]
첫 번째 오브젝트를 생성하고 이름을 'BG_Card'로 지정함. 위치는 (X: 0, Y: -1, Z: 0)으로 설정함.
두 번째 오브젝트를 생성하고 이름을 'Front_Item'으로 지정함. 위치는 'BG_Card'와 동일하게 (X: 0, Y: -1, Z: 0)으로 설정함.
'BG_Card'의 Sprite Renderer 색상을 파란색으로 변경하고, Order in Layer를 0으로 설정함.
'Front_Item'의 Sprite Renderer 색상을 빨간색으로 변경하고, Order in Layer를 1로 설정함.

[채점 기준]
Game 뷰에서 파란색 카드 위에 빨간색 사각형이 가려지지 않고 온전하게 위로 얹혀서 보여야 함.
제출된 에디터 화면의 Inspector 창에서 'Front_Item'의 Sprite Renderer 컴포넌트와 Order in Layer 값이 '1'로 입력된 상태가 선명하게 노출되어야 함.


문제 3: Rigidbody2D를 배제한 커스텀 중력 수식 및 충돌 정지 구현

[문제 설명]
물리 컴포넌트(Rigidbody2D)를 전혀 사용하지 않고, 순수 수식(중력 가속도)을 이용해 원형 오브젝트를 자유낙하 시킨 뒤 사각형 바닥 오브젝트와 충돌했을 때 멈추도록 한다.

[세부 요구사항]
1) 낙하 오브젝트 (원형):
- Hierarchy 창 우클릭 -> 2D Object -> Sprites -> Circle을 생성하고 이름을 'FallingBall'로 지정함.
- **Circle Collider 2D** 컴포넌트를 반드시 부착할 것. (Rigidbody2D 컴포넌트는 절대 부착하지 않음)
2) 바닥 오브젝트 (사각형):
- Hierarchy 창 우클릭 -> 2D Object -> Sprites -> Square를 생성하고 이름을 'GroundBlock'으로 지정함.
- 화면 하단(Y: -3.0 부근)에 가로로 길게 배치하고, **Box Collider 2D** 컴포넌트를 반드시 부착할 것.
3) 스크립트 작성 (컴포넌트 명: CustomGravityFall):
- 'FallingBall'에 부착할 C# 스크립트를 작성함.
- 중력 가속도 수식(속도 및 변위 연산, 혹은 사용자 정의 중력 변수)을 적용하여 매 프레임 Y축 좌표를 감소시켜 낙하를 구현함.
- 'GroundBlock'과 충돌(또는 접촉)하는 순간 하강을 멈추고 바닥 상단에 정확히 안착하도록 처리함.

[채점 기준]
- 에디터 상에서 'FallingBall'에 Rigidbody2D가 없는 상태로 Circle Collider 2D만 부착되어 있는지 Inspector 창에서 확인할 수 있어야 함.
- Play 버튼을 실행했을 때 공이 수식에 의해 자연스럽게 낙하하다가 바닥에 부딪혀 파묻히거나 통과하지 않고 정확히 멈춘 상태가 Game 뷰와 Scene 뷰에 동시에 드러나야 함.




문제 4: 마우스 클릭 기반 가속 및 배경 스크롤 인터랙션 연동 실기 평가

[문제 설명]
지금까지 강의에서 학습한 New Input System의 `Mouse.current` 폴링 입력, TextMeshPro 텍스트 UI 실시간 갱신, 그리고 Transform 컴포넌트를 이용한 오브젝트 이동 제어를 종합하여, 마우스 클릭 횟수에 따라 배경의 스크롤 속도가 단계적으로 빨라지는 인터랙션 시스템을 구현한다.

[카메라 및 화면 셋업 규격 (필수)]
- Game 뷰 해상도: 1920x1080 (16:9 Full HD) 고정
- Main Camera 세팅: Projection은 반드시 Orthographic으로 설정하고, Size는 5.0으로 맞출 것.
- 카메라 좌표: Position (X: 0, Y: 0, Z: -10)

[세부 요구사항]
1) 오브젝트 및 UI 구성:
- 화면 중앙(X: 0, Y: 0, Z: 0)에 배경 역할을 할 2D Sprite 오브젝트 'Background_Object'를 생성하고, 기존 강의에서 다룬 Transform 기반 이동/스크롤 스크립트를 부착할 것.
- Canvas 하위에 TextMeshProUGUI 요소를 생성하고 이름을 'Score_Text'로 지정하여 화면 상단에 배치할 것.
2) 마우스 입력 및 클릭 카운터 연동 (Lecutre04_Clicker 응용):
- New Input System의 `Mouse.current.leftButton.wasPressedThisFrame` 방식을 사용하여 마우스 왼쪽 클릭을 매 프레임 감지할 것.
- 마우스가 클릭될 때마다 내부 클릭 카운트(`clickCount`) 변수를 1씩 증가시키고, 'Score_Text'에 "Clicked Number: [숫자]" 형태로 즉시 갱신되도록 구현할 것.
3) Transform 및 속도 연동 응용:
- 마우스가 클릭될 때마다 배경 오브젝트의 이동 `speed` 값이 특정 수치(예: 클릭당 +1.0 또는 특정 배수)만큼 증가하여, 클릭할수록 배경이 더 빠르게 스크롤되도록 코드를 확장할 것.
- 이 과정에서 `Debug.Log`를 활용하여 현재 클릭 횟수와 현재 적용된 스크롤 `speed` 값을 콘솔창에 동시 출력할 것.

[채점 대기 상태 및 제출 기준]
- 유니티 에디터 레이아웃을 Game 뷰, Scene 뷰, Inspector 창, Console 창이 한눈에 보이도록 정렬할 것.
- Play 버튼을 누른 즉시 테스트가 가능하도록, 에디터 상에서 배경 오브젝트와 텍스트 UI가 올바른 위치에 배치된 상태로 대기할 것.
- 마우스 왼쪽 버튼을 연타했을 때 콘솔창의 속도 로그와 클릭 횟수가 일치하며, 화면의 텍스트 UI 숫자가 실시간으로 1씩 올라가고 배경의 이동 속도가 눈에 띄게 빨라지는 모습을 교사에게 제시하여 채점받을 것.
